# 设备停机原因分析（故障树最小割集）

供设备检修人员使用的停机原因分析网页：录入基础故障与 AND / OR 逻辑门，指定顶层故障后，系统自底向上计算使顶层故障发生的**最小基础故障组合**（最小割集），并列出每个组合涉及的基础故障。

## 快速启动（单条命令）

需要已安装 Docker 与 Docker Compose。在项目根目录执行：

```bash
docker compose up --build
```

依赖安装与初始化均已纳入镜像构建与启动流程，无需额外步骤。

启动后在浏览器访问：

```
http://localhost:3000
```

停止服务：`docker compose down`。

## 配置

| 环境变量 | 默认值 | 说明 |
| -------- | ------ | ---- |
| `PORT`   | `3000` | 服务监听端口（Compose 中已将容器的 3000 端口映射到本机 3000 端口） |

无数据库、无外部服务依赖，无需其他配置。

## 本地开发（不使用 Docker）

```bash
npm install
npm start        # 启动服务，访问 http://localhost:3000
npm test         # 运行核心算法单元测试
```

## 使用说明

1. **录入基础故障**：至多 12 个，名称不可重复。
2. **定义逻辑门**：每个门有名称、类型（AND / OR）和引用列表，引用可以是基础故障或已定义的门。
3. **指定顶层故障**：从已录入的基础故障或门中选择。
4. 点击「开始分析」，结果按**故障数升序、再按名称**排序展示，每行列出该组合涉及的基础故障。

页面提供「载入示例」按钮，可快速体验完整流程。

### 计算规则

- **OR 门**：汇总各子节点的组合（并集）。
- **AND 门**：合并各子节点的组合（笛卡尔积，每个结果取成员并集）。
- 每一步合并后都会**去重**并**删除包含更小组合的超集**，中间结果始终是最小割集，避免重复路径放大结果。

### 错误提示

以下情况会返回明确的错误信息：

- 门引用了不存在的故障或门；
- 门定义成环（含自引用），错误信息会指出环路径；
- 未指定顶层故障，或指定的顶层故障不存在；
- 基础故障超过 12 个、名称为空或重名等录入问题。

## 项目结构

```
├── server.js            # Express 服务：静态页面 + /api/analyze 接口
├── lib/analyze.js       # 故障树最小割集核心算法（校验 + 计算）
├── public/              # 前端页面（index.html / app.js / style.css）
├── test/analyze.test.js # 核心算法单元测试（node:test）
├── Dockerfile           # 镜像构建：安装依赖并启动服务
└── docker-compose.yml   # 单服务编排，映射 3000 端口
```

## API

`POST /api/analyze`

```json
{
  "basics": ["轴承磨损", "电机过热"],
  "gates": [{ "name": "停机", "type": "OR", "refs": ["轴承磨损", "电机过热"] }],
  "top": "停机"
}
```

成功响应：`{ "ok": true, "combinations": [["电机过热"], ["轴承磨损"]] }`
失败响应（HTTP 400）：`{ "ok": false, "error": "未指定顶层故障" }`
